# Changelog

Each date is the day of the upload to PyPI, in UTC ([nookku](https://pypi.org/project/nookku/#history), [verbatim-relay](https://pypi.org/project/verbatim-relay/#history)). 0.2.0 has no upload, so its date is the day of [its tag](https://github.com/mohanraj00/nookku/commit/v0.2.0).

## 0.4.1

Released 2026-10-13.

This release fixes defects in the relay, the tap, the record reader, the config reader and the evaluation. It also makes the CLI text and the docs clearer. The record format does not change. The reader refuses 2 kinds of record that 0.4.0 accepted: a number that is NaN or Infinity ([#96](https://github.com/mohanraj00/nookku/issues/96)).

- **Lone surrogate in a reply.** Both relay paths refuse a reply with a lone surrogate, with or without an entry. The turn has `ok: false`, and the error names the code point ([#93](https://github.com/mohanraj00/nookku/issues/93)).
- **Tap write error.** If the tap cannot write the row of a response that is not a stream, it answers 502 and writes the path and the OS error to stderr. The caller gets a response only after its row is in the record ([SPEC.md section 4.1](SPEC.md#41-http-mode), [#94](https://github.com/mohanraj00/nookku/issues/94)).
- **NaN and Infinity.** The Python reader refuses NaN and Infinity in a record, as the plugin does ([SPEC.md section 2](SPEC.md#2-record-format), [#96](https://github.com/mohanraj00/nookku/issues/96)).
- **Blank lines in the trace.** The ignored counts of the trace include the blank lines of a session file ([SPEC.md section 8](SPEC.md#8-trace), [#97](https://github.com/mohanraj00/nookku/issues/97)).
- **Astral characters.** A new audit case covers a blocked-call detail with astral characters ([#112](https://github.com/mohanraj00/nookku/issues/112)).
- **One config reader.** The `evaluate` key comes from the one config reader, and `read_config` checks the type of each value. An explicit `null` is now refused. If the file is broken, no evaluation starts and `nookku end` says why. The guard still uses each key that has the right type ([#119](https://github.com/mohanraj00/nookku/issues/119), [#121](https://github.com/mohanraj00/nookku/issues/121)).
- **Evaluation.** A test of `nookku check` gets no evaluation. The evaluation prompt tells the model what to do with an invalid record ([#102](https://github.com/mohanraj00/nookku/issues/102), [#103](https://github.com/mohanraj00/nookku/issues/103)).
- **CLI text.** The start text does not name the evaluation if it is off, and it gives the 2 ways to end a test. The invalid-choice error does not name an internal command. `check` shows each stray-line fix one time. `verify` prints the test id and names it in an error. A test argument can be the path of a test folder. `init` has `--no-openai-stream`. The plugin and the project hooks use one status text. The view shows the next turns after the record gets shorter ([#113](https://github.com/mohanraj00/nookku/issues/113), [#114](https://github.com/mohanraj00/nookku/issues/114), [#115](https://github.com/mohanraj00/nookku/issues/115), [#116](https://github.com/mohanraj00/nookku/issues/116), [#117](https://github.com/mohanraj00/nookku/issues/117), [#118](https://github.com/mohanraj00/nookku/issues/118), [#120](https://github.com/mohanraj00/nookku/issues/120), [#122](https://github.com/mohanraj00/nookku/issues/122), [#160](https://github.com/mohanraj00/nookku/issues/160)).
- **Docs.** The README has a new first screen, a 1-minute try with no model and an excerpt of a real report. The docs map is clean. "Harness" has one meaning, and the docs say "project hooks", not "hook kit". The docs and CI name the same harness versions. The examples have READMEs. Each docs page links the first use of each glossary term, and code-quality.md gives one copy of each rule ([#166](https://github.com/mohanraj00/nookku/issues/166), [#167](https://github.com/mohanraj00/nookku/issues/167), [#256](https://github.com/mohanraj00/nookku/issues/256), [#257](https://github.com/mohanraj00/nookku/issues/257), [#258](https://github.com/mohanraj00/nookku/issues/258), [#259](https://github.com/mohanraj00/nookku/issues/259), [#260](https://github.com/mohanraj00/nookku/issues/260), [#261](https://github.com/mohanraj00/nookku/issues/261), [#262](https://github.com/mohanraj00/nookku/issues/262)).
- **Release.** The release workflow starts only on a `v<number>` tag ([#254](https://github.com/mohanraj00/nookku/issues/254)).

## 0.4.0

Released 2026-10-12.

verbatim-relay is now Nookku. The package, the CLI, the module, the plugin, the marketplace, the state folder and the variables have the new name. The record format and the audit do not change.

**Upgrade.** End each running test. Then install `nookku`, update the plugin and run `nookku init` again. The first `nookku` command in a project moves `.verbatim-relay/` to `.nookku/`. [The upgrade guide](docs/how-to/upgrade.md#040) gives each step.

- **New name.** The package and the CLI are `nookku`, the module is `nookku`, and the plugin is `nookku@nookku`. The variables start with `NOOKKU_`, for example `NOOKKU_HOME`. The repo is `mohanraj00/nookku` ([#181](https://github.com/mohanraj00/nookku/issues/181), [#208](https://github.com/mohanraj00/nookku/issues/208), [#210](https://github.com/mohanraj00/nookku/issues/210)).
- **State folder move.** Each command with a project root moves `.verbatim-relay/` to `.nookku/`. A `record` path in the old folder changes to the same file in `.nookku/`. If both folders exist, the command stops and names both. A hook event is then blocked, so the relay fails closed ([SPEC.md section 7](SPEC.md#7-tests), [#181](https://github.com/mohanraj00/nookku/issues/181)).
- **Old seal copies.** `verify` reads the seal copy of an old test from `~/.verbatim-relay/seals/` if `~/.nookku/seals/` has no copy ([SPEC.md section 7.4](SPEC.md#74-seal), [#181](https://github.com/mohanraj00/nookku/issues/181)).
- **One core, one plugin.** [ADR 0001](docs/adr/0001-one-core-one-plugin.md) records the decision for one core and one plugin for both harnesses. It links the data and the method of each spike ([#176](https://github.com/mohanraj00/nookku/issues/176), [#177](https://github.com/mohanraj00/nookku/issues/177), [#178](https://github.com/mohanraj00/nookku/issues/178), [#179](https://github.com/mohanraj00/nookku/issues/179), [#180](https://github.com/mohanraj00/nookku/issues/180), [#193](https://github.com/mohanraj00/nookku/issues/193), [#194](https://github.com/mohanraj00/nookku/issues/194), [#205](https://github.com/mohanraj00/nookku/issues/205)).
- **Reply in the chat.** The hook kit shows each reply as the reason of the blocked prompt, byte for byte. Claude Code and Codex show the reason to the person and do not give it to the model. `codex exec` shows no reason, so `nookku view` stays ([#214](https://github.com/mohanraj00/nookku/issues/214)).
- **Faster hooks.** A hook event imports only the modules that its rule needs. Over the floor of the same run, a warm event takes 14 to 23 ms on Linux and on macOS (the second run of the data, with less load), not 28 to 34 ms ([data](proofs/hook-time/hook-latency.json), [method](scripts/spike_hook_latency.py), [#214](https://github.com/mohanraj00/nookku/issues/214)).
- **Hook with no root.** `nookku hook` finds the project from `CLAUDE_PROJECT_DIR` or the `cwd` of the event, if it gets no `--root` ([#214](https://github.com/mohanraj00/nookku/issues/214)).
- **MCP server.** `nookku mcp` gives the model the read-only tools `transcript` and `status`, with the standard library only. The transcript comes in pages with a footer and a SHA-256, so a page that a harness cut shows it. The default page got to the model unchanged in Claude Code and in Codex for 4 kinds of text ([data](proofs/mcp/transcript-pages.json), [method](scripts/measure_transcript_pages.py), [#215](https://github.com/mohanraj00/nookku/issues/215)).
- **One plugin for Claude Code and Codex.** The plugin folder is `plugins/nookku`, with a manifest for each harness, one command hook file, the MCP server `nookku mcp` and one skill. Each command hook runs `nookku hook`, so the plugin and the project hooks share one core. If `nookku` is not on `PATH`, a shell guard blocks the prompt in relay mode. The Claude Code function hooks only show the output of the core: `/nookku`, the status line and the pane. One exception: a command hook gets only the text of a prompt, so in relay mode the function hook drops a prompt with an attachment, with the text of the core. The plugin loads in Claude Code 2.1.295 and in Codex 0.162.0 ([data](proofs/plugin/load.json), [method](scripts/proof_plugin_load.py), [#216](https://github.com/mohanraj00/nookku/issues/216)).
- **Codex hook gate.** Codex skips a hook that a person did not trust, and then a message goes to the model. `start` and `mode on` now read the hooks of Codex with `hooks/list`, and refuse the test if a nookku hook is missing, disabled, not trusted or modified. The trust hash of Codex does not cover the plugin script, so the gate also checks its SHA-256. `end` checks again, and the manifest keeps both results. With the gate, the Codex marketplace lists the plugin as available ([SPEC.md section 7.8](SPEC.md#78-codex-hook-gate), [data](proofs/codex-gate/gate.json), [method](scripts/proof_codex_gate.py), [#217](https://github.com/mohanraj00/nookku/issues/217)).
- **Docs for one core.** The docs name one relay, `nookku hook`, in 2 forms: the plugin and the project hooks (the hook kit of 0.3). The plugin works in Claude Code and in Codex. [Choose the plugin or the project hooks](docs/how-to/choose-a-relay.md) compares them. SPEC.md section 5 and [limits.md](docs/limits.md) state that `claude -p` and the Codex desktop app can send a blocked prompt to the model API ([#199](https://github.com/mohanraj00/nookku/issues/199), [#203](https://github.com/mohanraj00/nookku/issues/203), [#218](https://github.com/mohanraj00/nookku/issues/218)).
- **Codex plugin upgrade.** The upgrade guide updates the Codex plugin with `codex plugin marketplace upgrade nookku` and `codex plugin add nookku@nookku`, not with a new install ([upgrade.md](docs/how-to/upgrade.md#3-update-the-plugin), [data](proofs/spikes/codex-plugin.json), [method](scripts/spike_codex_plugin.py), [#218](https://github.com/mohanraj00/nookku/issues/218)).
- **Proofs of one core.** `scripts/proofs_relay.py <setup>` runs P1 to P4 in 4 setups: the plugin and the project hooks, each in Claude Code and in Codex. It replaces the proof scripts of the TypeScript plugin. The report, telemetry and evaluation proofs take the same setup names. Each proof passed in each setup with nookku 0.3.1 ([results.md](docs/results.md#1-proofs), [#219](https://github.com/mohanraj00/nookku/issues/219)).
- **Sample outputs.** The docs show the output of nookku 0.4.0, in place of the output of verbatim-relay 0.3.0. A model answer and a command that changes the install of the computer keep the output of 0.3.0, and each page says so ([#212](https://github.com/mohanraj00/nookku/issues/212)).
- **No plugin options.** The plugin reads `.nookku/config.json`. Write it with `nookku init plugin`, which writes no project hooks. `nookku mode on` with no config keeps relay mode off ([#216](https://github.com/mohanraj00/nookku/issues/216)).
- **No record limit.** The plugin no longer stops at a relay record of 3.5 MiB, because the core writes the record ([#216](https://github.com/mohanraj00/nookku/issues/216)).
- **Policy file.** `.nookku/policy.json` holds the keys that control the guard. Only a person changes it, with `nookku policy set` in a shell. The relay denies each model write to the file, also when no test runs and in a project with no `.nookku/` folder. The manifest records the value of each key. Its first key is `guard_fields` ([SPEC.md section 7.9](SPEC.md#79-policy-file), [#175](https://github.com/mohanraj00/nookku/issues/175)).
- **Guard checks paths.** The deny of the state folder checks the paths that a tool call writes, not its text. When no test runs, a tool call can change `config.json` and the files of the entry, and the relay denies only a write to a record or a state file. A file whose content names a record, or a here-document that is data, is not denied. Each reason names the path ([SPEC.md section 5](SPEC.md#5-relays), [#149](https://github.com/mohanraj00/nookku/issues/149)).
- **Guard fields.** For an MCP tool or another tool that is not a shell or a file tool, the guard reads only the fields of the policy key `guard_fields`: by default `path`, `file_path`, `url`, `uri` and `command`. A document body that names the state folder or the tap is not denied ([SPEC.md section 5](SPEC.md#5-relays), [#150](https://github.com/mohanraj00/nookku/issues/150)).
- **Read commands and deny causes.** The read check accepts `which`, `type` and `command -v`, and the programs of the new policy key `guard_reads`. The records deny names the program or the redirect that failed, for example `"rm" is not a read command.` A variable can be an argument of a read program, but not the program ([SPEC.md section 5](SPEC.md#5-relays), [#172](https://github.com/mohanraj00/nookku/issues/172)).
- **Both forms on.** In Claude Code, `start` and `mode on` refuse a test if the nookku plugin and the project hooks are both on, as the Codex hook gate does. `init` warns if the other form is on ([SPEC.md section 7.8](SPEC.md#78-codex-hook-gate), [#151](https://github.com/mohanraj00/nookku/issues/151)).
- **Remove the project hooks.** `nookku init --remove claude-code` or `nookku init --remove codex` removes the hooks of nookku from the hook file, and keeps each other hook and key. You do not need `jq` now. It refuses while a test runs or relay mode is on. Only a person runs it: the relay denies it to a model ([remove.md](docs/how-to/remove.md#2-remove-the-project-hooks), [#163](https://github.com/mohanraj00/nookku/issues/163)).
- **Test folder for the app.** The entry gets `NOOKKU_TEST_DIR` and `NOOKKU_TEST_ID`. An app can keep its state in `app-state/` of the test folder. The seal covers it, and the evaluation reads it. The toy shop writes `app-state/answers.jsonl` ([SPEC.md section 6.1](SPEC.md#61-environment-of-the-entry), [#145](https://github.com/mohanraj00/nookku/issues/145)).
- **Check message.** The new config key `check_message` sets the one message of `nookku check`, and `init` takes `--check-message`. An app that declines the default message can now get a message that it answers ([SPEC.md section 7.1](SPEC.md#71-configuration), [#147](https://github.com/mohanraj00/nookku/issues/147)).
- **Repeated reply.** The new trace check `repeated_reply` gives one finding for each run of 2 or more consecutive turns with the same reply bytes, for example a fixed fallback text. It is a finding, not a break. The new config key `repeated_reply` sets the count, and 0 turns the check off. `init` takes `--repeated-reply`, and the manifest records the value ([SPEC.md section 8.6](SPEC.md#86-findings), [#155](https://github.com/mohanraj00/nookku/issues/155)).
- **Compact transcript.** `nookku transcript --trace --compact` shows a repeated prompt one time. After that, it shows the line, the SHA-256 and the length. An OpenTelemetry attribute with the text of a session item of the same turn also shows in this form. The new config key `transcript_compact` sets the default, and `--no-compact` overrides it. The `transcript` tool of `nookku mcp` takes `compact` ([SPEC.md section 9.2](SPEC.md#92-evaluation-prompt), [#152](https://github.com/mohanraj00/nookku/issues/152)).
- **Reply not from the model.** The new trace check `reply_not_from_model` gives a finding for each turn whose reply does not contain the text of a model output of that turn, for example a fixed decline text in place of the model text. It is a finding, not a break. The new config key `model_reply_field` names the client text in a structured model output, and `model_reply_match` is `exact`, `normalized` (the default) or `off`. `init` takes `--model-reply-field` and `--model-reply-match`, and the manifest records both values ([SPEC.md section 8.6](SPEC.md#86-findings), [#154](https://github.com/mohanraj00/nookku/issues/154)).
- **Scripted tests.** `nookku run --script <file>` sends each message of a script file to the entry, byte for byte, and ends the test. The script is JSONL with `{"said": "..."}` rows or one JSON array of strings. The test folder keeps a copy, each relay row has `"harness": "script"`, and the new break class `script_mismatch` names a turn that is not its script message. The new config key `entries` names more entries, and `--entry` takes only such a name. If the policy key `scripts` is `model`, the model can run a script with `nookku run` or with the `run_script` tool of the plugin ([SPEC.md section 7.10](SPEC.md#710-scripted-tests), [#171](https://github.com/mohanraj00/nookku/issues/171)).
- **Drive commands.** The guard denies a model command that runs `nookku start`, `end`, `hook`, `run` or `mode on|off`, or that imports the package. The new policy key `scripts` lets the model run `nookku run` ([SPEC.md section 5](SPEC.md#5-relays), [#173](https://github.com/mohanraj00/nookku/issues/173)).
- **Near-miss control prompts.** In relay mode, the relay refuses a message near a control prompt, for example `nookku stop` or `nookk end`, and sends nothing. The refusal lists the control prompts. The new policy key `control_distance` sets the edit distance, default 2 ([SPEC.md section 5](SPEC.md#5-relays), [#146](https://github.com/mohanraj00/nookku/issues/146)).
- **`init` in the state folder.** `init` refuses a root in `.nookku/`, for example a test folder, and writes nothing. It warns if a new root is not the top level of its git work tree. Its output starts with the absolute root ([docs/reference/cli.md](docs/reference/cli.md#nookku-init), [#148](https://github.com/mohanraj00/nookku/issues/148)).
- **One line for each untested version.** The transcript with the trace shows the `version_untested` findings of one harness and one version as one line, with the count of sessions. `findings.json` still has one finding for each session ([SPEC.md section 9.2](SPEC.md#92-evaluation-prompt), [#153](https://github.com/mohanraj00/nookku/issues/153)).
- **Tool events by id.** The check `otel_tool_not_in_session` looks only at the tool calls of the session of the event. It matches a Claude Code `tool_result` event to its tool call by the tool use id, if both have one. Else it compares the tool name and the input in the same turn, and a cut string of the event agrees with the start of the session string. A structured output that the model sends 2 times in one turn now gives no finding ([SPEC.md section 8.6](SPEC.md#86-findings), [#174](https://github.com/mohanraj00/nookku/issues/174)).
- **Last verbatim-relay.** The package `verbatim-relay` 0.4.0 has no dependency and does not install `nookku`. Its command prints one line with the new name and the link to the upgrade guide, and exits with 1 ([tests/test_redirect.py](tests/test_redirect.py)). It does not run `nookku`. `import verbatim_relay` gives the same message as an `ImportError`. An old project hook runs `python -m verbatim_relay hook`. It prints the same line and exits with 2, so the hook blocks the event and no prompt goes to the model. A separate workflow publishes it from a `verbatim-relay-v*` tag ([#213](https://github.com/mohanraj00/nookku/issues/213)).
- **Old kit hooks.** `nookku init` replaces the hooks that verbatim-relay wrote, so the harness runs one hook for each event ([#181](https://github.com/mohanraj00/nookku/issues/181)).

## 0.3.0

Released 2026-10-08.

Streamed replies, and the fixes of the 0.2 code review. An agent can now stream its reply, and the relays still show and record it byte for byte. Each relay path fails closed: if a hook or a guard fails, the prompt does not reach the model, and the tester sees the cause and the next step. Each record has one reader with one rule in Python and in the plugin. Both taps have one deadline, and the proxies keep no secret query value. The docs have a tutorial, how-to guides, reference pages and an architecture page. [The proofs](docs/results.md) pass in the plugin, the hook kit in Claude Code and the hook kit in Codex.

**Upgrade.** End each running test before you upgrade. `current.json` now needs `pid_start` ([#44](https://github.com/mohanraj00/nookku/issues/44)), so 0.3.0 treats a test that 0.2.0 started as not running.

- **Streamed replies.** If the agent answers with an SSE stream (`text/event-stream`), the tap sends each part to the relay when it comes, and records the complete reply when the stream ends. The relay shows the reply when the stream is complete. A stream that ends early, sends an error or has a malformed chunk gives an error, not a part of the reply. The option `openai_stream` (`--openai-stream` in the hook kit) makes both relays send `"stream": true`, for an agent that streams only on request. [SPEC.md section 4.1](SPEC.md#41-http-mode) defines the rules ([#1](https://github.com/mohanraj00/nookku/issues/1), [#66](https://github.com/mohanraj00/nookku/issues/66)).
- **Record format v0.3.** The row of a failed stream (a 2xx status with `reply: null`) has version `0.3`. Each other row keeps `0.2`, so a 0.2.0 reader still reads it, and refuses a 0.3 row with a message that names the version. Readers accept `0.1`, `0.2` and `0.3` ([SPEC.md section 2](SPEC.md#2-record-format), [#66](https://github.com/mohanraj00/nookku/issues/66)).
- **Stream errors.** If the tap cannot write the row of a stream, it sends no second status and writes no second row. With a `Content-Length`, it holds the last byte until the row is in the record, so the caller sees an incomplete response. The model API proxy and the tap read SSE with one strict parser ([#66](https://github.com/mohanraj00/nookku/issues/66)).
- **Fail closed in the plugin.** Each gating hook of the plugin has a `.catch` handler. If a hook fails or runs past its time budget, the handler blocks the prompt or denies the tool call, and it makes no file or state call that can stall again ([#63](https://github.com/mohanraj00/nookku/issues/63)).
- **Fail closed in the hook kit.** A PreToolUse deny with a broken config, or with an error in the guard, still denies the call in relay mode or during a test ([#68](https://github.com/mohanraj00/nookku/issues/68)).
- **Stale test.** If the plugin cannot reach the tap of `current.json`, it asks `verbatim-relay status`. If no test runs, it shows "the test stopped, and no test runs" and the next step. The turn stays in the record with `ok: false`, because the prompt can have reached the tap ([#64](https://github.com/mohanraj00/nookku/issues/64)).
- **Bridge identity.** `current.json` has `pid_start`, the start time of the bridge process. A test whose pid now belongs to another process is not running, and `end` sends no signal to that process ([#44](https://github.com/mohanraj00/nookku/issues/44)).
- **One reader.** Each part reads a record with `record.read_rows`, and the plugin reads the relay record with `relayTurns` and the same rule. A bad line stops the reader with an error that names the file and the line. The transcript of an invalid record shows no turn. The shared table `RELAY_LINES` checks the 2 readers against the conformance cases. If `relay.jsonl` is invalid at the end of a test, the bridge infers no Codex session ([#71](https://github.com/mohanraj00/nookku/issues/71)).
- **One contract reader.** `contract.parse_reply` and the plugin refuse a line with both `reply` and `error`, and `NaN` or `Infinity`. The shared table `CONTRACT_LINES` checks both readers against the contract cases ([#45](https://github.com/mohanraj00/nookku/issues/45)).
- **One config rule.** `start`, `check`, `init` and the hook kit read `.verbatim-relay/config.json` with one reader. An unknown key stops each of them with the same error. Before, `start` accepted it, and then the hook kit blocked each prompt. A second `init` keeps each key of the file, for example `backends` and `"evaluate": false`, and changes only the keys of its flags. It prints the changed and the kept keys ([SPEC.md section 7.1](SPEC.md#71-configuration), [#89](https://github.com/mohanraj00/nookku/issues/89)).
- **Lone surrogates.** A row with a lone surrogate is invalid (`record_invalid`), not a crash. The relays refuse a prompt with a lone surrogate and say why. The trace, the OTLP receiver and the proxies write a lone surrogate as its escape text, so a write never fails ([#43](https://github.com/mohanraj00/nookku/issues/43), [#65](https://github.com/mohanraj00/nookku/issues/65)).
- **Stray lines in stdio mode.** The stdio tap reads lines until it gets the line for the request id. A log line on stdout is a stray line with its own `unparsed` row, not a 502. A timeout after stray lines names them and gives the fix. `serve()` sends the output that the entry printed before it to stderr ([#62](https://github.com/mohanraj00/nookku/issues/62), [#46](https://github.com/mohanraj00/nookku/issues/46)).
- **Check gate.** `verbatim-relay check` reads the audit of its own test. If the audit exit is not 0, the check fails, with one FAIL line and its fix for each error and each break. If `audit.json` is missing or not valid, the check fails. A line that the entry writes on stdout after its last reply is a stray line too ([SPEC.md section 7.1](SPEC.md#71-configuration), [section 4.2](SPEC.md#42-stdio-mode), [#90](https://github.com/mohanraj00/nookku/issues/90)).
- **Blocked-call detail.** Both relays cut the `detail` of a `blocked_call` row at 300 code points, so a cut never splits a surrogate pair and the relay record stays valid. The shared table `DETAIL_CASES` checks both relays ([SPEC.md section 2.2](SPEC.md#22-relay-record), [#88](https://github.com/mohanraj00/nookku/issues/88)).
- **Record errors in the view.** In follow mode, `view` writes an error for an invalid relay record to stderr, and shows the next turns when the record is valid again. `view --no-follow` writes the error and exits with 2 ([docs/reference/cli.md](docs/reference/cli.md), [#92](https://github.com/mohanraj00/nookku/issues/92)).
- **Start and status texts.** The start text of both relays names the prompt `verbatim-relay end`, which ends the test and starts the evaluation, and the end with no evaluation. The plugin status asks `verbatim-relay status --json`, so a stale `current.json` does not show as a running test. `--help` does not show the internal `bridge` command ([SPEC.md section 5](SPEC.md#5-relays), [#91](https://github.com/mohanraj00/nookku/issues/91)).
- **One deadline.** Both taps wait [240 seconds](src/nookku/stdio.py) for the agent, as one deadline for the connection, the headers and the body, also for a stream. Each timeout of the relay path ends before the next one, and [one test](tests/test_timeouts.py) checks the order ([SPEC.md section 4.3](SPEC.md#43-timeouts), [#67](https://github.com/mohanraj00/nookku/issues/67)).
- **Deny.** Both relays deny a model command that writes to `/dev/tcp` or `/dev/udp` paths of the tap or the agent, also with leading zeros in the port. The shared table `DENY_CASES` checks both deny patterns ([#70](https://github.com/mohanraj00/nookku/issues/70)).
- **No secret query values.** The backend and model API proxies remove the values of secret query parameters from the record, and forward them with no change ([#69](https://github.com/mohanraj00/nookku/issues/69)).
- **Transcript.** The plugin and the hook kit give the model one rendered transcript, with a legend for `ok` and for a relay error, and with no hashes ([SPEC.md section 5](SPEC.md#5-relays), [#10](https://github.com/mohanraj00/nookku/issues/10)).
- **OpenAI Responses and Decisions APIs.** The model API proxy reads the result of `/responses` calls, also streamed, and of `/decisions` calls. The trace and the evaluation view show them ([SPEC.md section 7.7](SPEC.md#77-model-api-proxies), [#33](https://github.com/mohanraj00/nookku/issues/33), [#40](https://github.com/mohanraj00/nookku/issues/40)).
- **Isolated Agent SDK session.** The toy apps start their Agent SDK session with `setting_sources=[]`, `strict_mcp_config=True` and no plugin folders. The new trace check `server_not_from_app` names an MCP server that the app's configuration cannot give ([#28](https://github.com/mohanraj00/nookku/issues/28)).
- **Docs.** A one-screen README, a docs map, a tutorial ([docs/getting-started.md](docs/getting-started.md)), how-to guides, reference pages for the CLI, the config and the records, an architecture page, troubleshooting and a FAQ. A code of conduct (Contributor Covenant 2.1), issue and PR templates, and a code quality spec ([docs/code-quality.md](docs/code-quality.md)). Tests check each relative link, the README counts, and the CLI and config pages against the code ([#72](https://github.com/mohanraj00/nookku/issues/72), [#73](https://github.com/mohanraj00/nookku/issues/73)).
- **Claims.** The README marks the prompt-only examples as single observations, and the benchmark text says that each turn was a new harness call ([#9](https://github.com/mohanraj00/nookku/issues/9), [#8](https://github.com/mohanraj00/nookku/issues/8)).
- **CI.** GitHub Actions are pinned to commit SHAs ([#4](https://github.com/mohanraj00/nookku/issues/4)).
- **Counts.** 53 audit cases in [conformance/cases/](conformance/cases/), 20 contract cases in [conformance/contract/](conformance/contract/), 10 trace cases in [conformance/trace/](conformance/trace/), 11 seal cases in [conformance/seal/](conformance/seal/) and 7 receiver cases in [conformance/otlp/](conformance/otlp/) ([cases](conformance/build.py)). The trace has [12 checks](src/nookku/trace.py).

## 0.2.0

Released 2026-10-07.

The telemetry MVP ([#27](https://github.com/mohanraj00/nookku/issues/27)). For each turn of a test, the record shows each action of the app that can change the reply or the state: its model sessions, its OpenTelemetry spans and logs, its backend calls and its direct model calls. Each action has its turn and its evidence line. The seal shows a changed record, and the evaluation at the end of a test cites these items. [The full telemetry proof](docs/results.md#full-telemetry-with-one-app) passes in the plugin, the hook kit in Claude Code and the hook kit in Codex.

- **Tests.** The harness starts the app. `verbatim-relay start` (or `/verbatim-relay start` in the plugin) starts an entry through the tap and switches relay mode on. `verbatim-relay end` stops it. The agent needs no HTTP server and no extra terminal. Each test has a folder in `.verbatim-relay/tests/` with both records, `app.log` and a manifest.
- **Agent contract v1.** One JSON line in and one JSON line out on stdin and stdout: a message, the history and a session in; a reply or an error out. `verbatim_relay.agent.serve(reply)` speaks it for a Python function. The tap's `--cmd` mode starts the agent and speaks it.
- **Model sessions.** The tap finds the app's own Claude Code sessions by their process, and its Codex sessions by their folder and time. At the end, it copies their session files into the test folder.
- **Trace.** At the end of a test, the bridge reads the copied session files into `trace.jsonl`: each message, tool call and command of the app's model sessions, with its result, its turn and its line in the session file. 11 checks write `findings.json`, with the checks of the later entries below. `verbatim-relay trace` builds both again. [SPEC.md section 8](SPEC.md#8-trace) defines them, and 7 conformance cases in [conformance/trace/](conformance/trace/) test them ([cases](conformance/build.py), [test](tests/test_trace.py)).
- **Evaluation.** The prompt `verbatim-relay end` ends the test and gives the harness model the evaluation prompt, in the plugin and in the hook kit. The model reads the transcript with the trace (`verbatim-relay transcript --trace`), the findings and the audit, checks the app, and writes `report.md` in the test folder. `"evaluate": false` in the configuration stops it. After a test, the relays deny model writes to a test folder, except `report.md`. [SPEC.md section 9](SPEC.md#9-evaluation) defines it. [Proofs P5 and P6](docs/results.md#p5-and-p6-the-evaluation-at-the-end-of-a-test) pass with the plugin and the hook kit in Claude Code, and with the hook kit in Codex: the report finds a planted business-rule bug.
- **Deny of the entry and the records.** During a test, both relays deny a model command that runs the entry, for example `python entry.py`. After a test, a model command that names `.verbatim-relay` can only read, or write `report.md`. A list of read programs in [SPEC.md section 5](SPEC.md#5-relays) defines "only read". Each other command and each tool that is not a shell is denied ([#20](https://github.com/mohanraj00/nookku/issues/20)).
- **Seal.** At the end of a test, the bridge writes the SHA-256 of each file of the test folder to `seal.json`, and a copy to `~/.verbatim-relay/seals/`. `verbatim-relay verify` shows each file that changed after the end, and exits with 2 if the seal is broken. `transcript --trace` shows the result in its first line. `verbatim-relay trace` rebuilds the trace only from sources that agree with the seal. Denies after a test go to `denied.jsonl`. [SPEC.md section 7.4](SPEC.md#74-seal) defines the seal, and 11 conformance cases in [conformance/seal/](conformance/seal/) test it ([#21](https://github.com/mohanraj00/nookku/issues/21)).
- **OpenTelemetry.** During a test, the bridge runs an OTLP/HTTP receiver and gives the entry its address in the `OTEL_*` variables. It takes JSON and protobuf (with a decoder that uses only the standard library), also with gzip, and writes `otel.jsonl`. It drops metrics and the spans of the harnesses, keeps the prompt, tool and reply events of the harnesses, and removes personal attributes. The trace reads `otel.jsonl` as `span` and `log` items (trace rows `0.3`, with the new field `service`), with 2 new checks: `span_error`, and `otel_tool_not_in_session`, which compares the tool events of the harness with its session file. `"otel": false` stops it. [SPEC.md section 7.5](SPEC.md#75-otlp-receiver) defines it. 6 receiver cases in [conformance/otlp/](conformance/otlp/) and 1 trace case test it ([#23](https://github.com/mohanraj00/nookku/issues/23)).
- **Backend calls.** The config key `backends` lists the HTTP services of the app. During a test, the bridge runs a recording proxy for each one, and gives the entry the proxy URL in the backend's environment variable. The proxy forwards each byte, also to an HTTPS backend, and writes `backend.jsonl` without the values of secret headers. The trace reads it as `http` items, with the new check `backend_error`. [SPEC.md section 7.6](SPEC.md#76-backend-proxies) defines it, the trace case `backend_toy_shop` tests it, and [proofs/backend/](proofs/backend/results.json) shows 3 calls with the same bytes at the entry, the service and the record ([#24](https://github.com/mohanraj00/nookku/issues/24)).
- **Direct model calls.** During a test, the bridge runs a recording proxy for the Anthropic and the OpenAI API, and gives the entry its URL in `ANTHROPIC_BASE_URL` and `OPENAI_BASE_URL`. The proxy sends each part of a streamed (SSE) response to the app when it comes, and writes `model_api.jsonl` with the text, the tool calls and the stop reason of each call. It removes the API key from the record. It keeps no text of a call from a harness, for example the Agent SDK, because that call holds the harness's own instructions. The trace reads the other calls as `message` and `tool_call` items, with the new check `model_api_error`. `"model_api": false` stops it. [SPEC.md section 7.7](SPEC.md#77-model-api-proxies) defines it, the trace case `model_api_toy_shop` tests it, and [proofs/model-api/](proofs/model-api/results.json) shows 3 calls with the same bytes at the entry, the toy API and the record, and 2 streams that reached the entry before their end ([#25](https://github.com/mohanraj00/nookku/issues/25)).
- **Example.** `examples/toy-shop-models/` is a toy shop with a Claude Agent SDK session, 2 tools and a planted bug.
- **Full example.** `examples/toy-shop-full/` is a toy shop with 3 parts: a Claude Agent SDK session with 3 tools, a stock service over HTTP, and a direct call to a case-note model with the OpenAI Chat Completions API and a stream. Its planted bug shows only in the backend calls. `toy_model.py` is a toy note model that needs no API key.
- **Full telemetry proof.** `scripts/proof_telemetry.py` runs a test of `examples/toy-shop-full/` in each relay. Each turn has items from the Agent SDK session file, the backend proxy and the model API proxy, and each report cites the 2 backend calls of the planted bug ([results](docs/results.md#full-telemetry-with-one-app), [#26](https://github.com/mohanraj00/nookku/issues/26)).
- **Agent SDK pin.** The proof scripts take the Agent SDK version from one pin in `scripts/proof_common.py`, now 0.2.164. The trace readers now also cover Claude Code 2.1.292, which this SDK bundles ([proofs/trace/](proofs/trace/results.json), [#35](https://github.com/mohanraj00/nookku/issues/35)). The proof scripts split model output on `\n` only ([#31](https://github.com/mohanraj00/nookku/issues/31)).
- **Model API URLs in the config.** `model_api` can also be an object from an API name to its upstream URL, for example when the tester's harness reads the same variable ([SPEC.md section 7.7](SPEC.md#77-model-api-proxies)).
- **Setup.** `verbatim-relay setup` prints the guide that a harness model follows to write the entry for an app. `verbatim-relay check` runs a test with one message and checks the reply and the model sessions. The plugin has a `setup` skill.
- **Hook kit.** The prompts `verbatim-relay start`, `verbatim-relay end` and `verbatim-relay status` control a test from inside Codex or Claude Code. During a test, both relays deny model changes to `.verbatim-relay/`.
- **Record format v0.2.** The `exchange` row gets `started`. The tap record gets the `model_session` row. The audit reads v0.1 and v0.2 rows and counts the model sessions. The matching does not change.
- **Fix.** The hook kit read the relay record with `str.splitlines()`, which also splits on U+2028. After a tester message with that character, each later message failed closed. The kit now splits on `\n` only.
- **Examples.** The toy shop agent speaks the agent contract. The HTTP version is `examples/toy-shop/http_agent.py`.
- **Docs.** A worked evaluation of the toy shop agent, with what the model found and what it got wrong: `docs/evaluation-example.md`.

## 0.1.0

Released 2026-10-06.

The first release.

- **Relays.** A Claude Code plugin (function hooks) shows each reply in the chat. A hook kit for Codex and Claude Code (classic hooks) shows each reply in `verbatim-relay view`. In relay mode, the model does not run.
- **Transcript.** After the test, the model reads the exact conversation: the plugin's `transcript` tool, or `verbatim-relay transcript`.
- **Tap.** `verbatim-relay tap` records what the agent received and sent. Adapters: a JSON body with configurable field paths, and OpenAI-compatible chat completions.
- **Audit.** `verbatim-relay audit` compares the two records and reports 7 break classes. It exits 0, 1 or 2, and it fails closed.
- **Spec and evidence.** Record format v0.1 in SPEC.md with 33 conformance cases. Proofs P1 to P5 on Claude Code 2.1.288 and Codex 0.160.0, and a pre-registered benchmark: 0 breaks in 1,000 turns.
