# Limits

This page lists what Nookku does not do, and what it does not prove. [results.md](results.md#3-what-this-does-not-prove) lists the limits of the proofs.

- **The deny is best effort.** The [relay](reference/glossary.md#relay) denies a model tool call that names the address of the [tap](reference/glossary.md#tap) or the agent. A model can try another way, for example an address alias. The [audit](reference/glossary.md#audit) finds every message that goes through the tap. A call that goes to the agent directly, around the tap, is in neither record, so give the model no direct route to the agent. After a test, a model command that names `.nookku` can only read, or write `report.md`. This deny is also best effort ([SPEC.md section 5](../SPEC.md#5-relays)). At the end, the [bridge](reference/glossary.md#bridge) [seals](reference/glossary.md#seal) the [test folder](reference/glossary.md#test-folder). `nookku verify` shows each file that changed after the end, and the [evaluation](reference/glossary.md#evaluation) sees the result ([SPEC.md section 7.4](../SPEC.md#74-seal)).
- **It is not a security boundary.** Do not use Nookku to keep a model away from a system. Read [SECURITY.md](../SECURITY.md).
- **The display layer of the [plugin](reference/glossary.md#plugin) in Claude Code uses function hooks.** They are early access and can change between releases. If they fail, `/nookku`, the status line and the pane stop, and the command hooks still relay each message. They hold one rule: in [relay mode](reference/glossary.md#relay-mode), they drop a prompt with an attachment. If they fail, the command hooks relay the text of that prompt, and the agent does not get the attachment. I pin the tested version and run the proofs again for each new one.
- **The relay shows a reply only as the reason of a blocked prompt.** `codex exec` does not show that reason, and in the interactive CLI the start of a long reply can go off the screen ([data](../proofs/spikes/hook-display.json)). `nookku view` shows each reply in a second terminal.
- **The model sessions come from the [harness](reference/glossary.md#harness)'s own files.** The harness binary writes them, not your app. Their format can change between harness versions. If your app turns them off (`persistSession: false` in the Agent SDK, `ephemeral: true` in Codex), the test has no copy, and `nookku check` says so. A Codex session must run in the project folder or below it. The [trace](reference/glossary.md#trace) readers cover the session files of Claude Code 2.1.286 ([data](../proofs/trace/results-2.1.286.json)) and 2.1.292 ([data](../proofs/trace/results.json)), and codex-cli 0.160.0 ([data](../proofs/trace/results-0.160.0.json)) and 0.162.1 ([data](../proofs/trace/results.json)). The method is [scripts/proof_trace.py](../scripts/proof_trace.py). For another version, the trace still runs, and `findings.json` says that the version is not tested.
- **The app's model sessions can show in your own session list.** Claude Code keeps the session files of a working folder in one folder of `~/.claude/projects/`, and `claude --resume` lists the sessions of the current folder. Codex filters `codex resume` by the working folder in the same way. If the app runs its harness in the project root, each test adds the app's sessions to your list. Nookku does not change or move these files ([SPEC.md section 7.3](../SPEC.md#73-model-sessions)). To keep them apart, run the harness of the app in a subfolder of the project. [troubleshooting.md](troubleshooting.md#the-apps-sessions-show-in-claude---resume-or-codex-resume) gives the steps.
- **The [entry](reference/glossary.md#entry) is in the message path.** The [harness model](reference/glossary.md#harness-model) writes it. The [tap records](reference/glossary.md#tap-record) only what goes in and out of the entry. Review it before a test. During a test, the relay denies model edits to `.nookku/` and model commands that run the entry. The manifest keeps the SHA-256 of each file in `.nookku/`.
- **Codex runs a hook only after you trust it.** This applies to the plugin and to the [project hooks](reference/glossary.md#project-hooks). Nookku never does the trust step. `nookku start` refuses a test if a nookku hook is missing, disabled, not trusted or modified. The gate checks again at the end, but it cannot stop a change during the test. The manifest records both results ([SPEC.md section 7.8](../SPEC.md#78-codex-hook-gate)).
- **Claude Code out of the interactive CLI can send a blocked prompt to the model API.** In print mode (`claude -p`), Claude Code can send the first prompt of a session in a request that makes the session title. I tested Claude Code 2.1.296 with `CLAUDE_AGENT_SDK_VERSION` set, as an Agent SDK app does. Then this occurred in 12 of 12 print mode runs, for the plugin and the [project hooks](reference/glossary.md#project-hooks). The interactive CLI did this in 0 of 18 runs. `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` stopped it in 12 of 12 runs. The data is `cases[].summary` in [the print mode data](../proofs/spikes/print-mode.json), and the method is [scripts/spike_print_mode.py](../scripts/spike_print_mode.py). The data does not cover a real Agent SDK app or another client of Claude Code. See [#199](https://github.com/mohanraj00/nookku/issues/199) and the [upstream report](https://github.com/anthropics/claude-code/issues/100695). Thus the Claude Code [relay](reference/glossary.md#relay) refuses each session that is not the interactive CLI. It does not start a test, and it does not relay a message ([SPEC.md section 5](../SPEC.md#5-relays)). To use another session, set `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` before you start Claude Code. The refusal cannot stop the title request of the prompt that it blocks.
- **A blocked main turn does not prove that the prompt reached no model.** The Codex desktop app can send a blocked prompt to the model API in a separate request. The relay does not cause that request. The measured versions and marker locations are in [the hook display data](../proofs/spikes/hook-display.json), at `codex.desktop.version` and `codex.desktop.model_requests`. The method is [scripts/spike_hook_display.py](../scripts/spike_hook_display.py), `codex --desktop`. See [#203](https://github.com/mohanraj00/nookku/issues/203). Do not use the desktop relay when a test needs to keep each [tester](reference/glossary.md#tester) prompt out of every model request. The CLI results in that data are a tested bound, not a guarantee for each version or client.
- **Desktop chat title generation can use a blocked prompt.** The follow-up capture matches the title generator's response schema. Its data is at `codex.desktop_side_requests` in [the same file](../proofs/spikes/hook-display.json), with the source inspection at `codex.side_request_investigation.source_inspection`. The method is `codex --side-requests` in the same script. In this capture, the blocked first prompt reached title generation in each new chat. The later blocked prompts appeared in no classified JSON model request. The absence claim does not cover the other HTTP requests that had no model field. The capture keeps no full bodies for those requests. This does not prove that only first prompts can reach a side request. I found no verified setting that stops it. `init` and the plugin do not set an unverified key, and hook trust does not establish that the desktop sends no side request.
- **The relay shows a streamed reply only when the stream is complete.** It does not show each part. With an entry, the entry joins the stream into one reply, in any stream format. Only the HTTP tap needs the `openai` adapter for a stream ([how-to/test-a-streaming-agent.md](how-to/test-a-streaming-agent.md)).
- **A report is a model answer.** It can miss an issue or name a wrong line. [evaluation-example.md](evaluation-example.md) shows one report and what the model got wrong.
- **A command hook gets only the text of a prompt.** In relay mode, the Claude Code plugin drops a prompt with an attachment. The project hooks and the Codex plugin cannot see the attachment, so they relay the text and drop the image. The Claude Code data is in [load.json](../proofs/plugin/load.json). The hook input schema of Codex 0.162.0 has no attachment field ([#216](https://github.com/mohanraj00/nookku/issues/216)).
- **Not yet:** attachments and images ([#6](https://github.com/mohanraj00/nookku/issues/6)), harnesses other than Claude Code and Codex, and tests on Windows.
