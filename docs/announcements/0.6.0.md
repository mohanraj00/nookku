## The text

> **Nookku 0.6.0: the evidence under the scores of your agent**
>
> An [evaluation](../reference/glossary.md#evaluation) platform scores conversations with your agent. It simulates users, runs judges and shows the scores of each release. Nookku does not replace that platform. Nookku is the layer under it. It tells you if the conversation that you score is the conversation that occurred.
>
> You talk to your agent app from Claude Code or Codex. Nookku carries each message and each reply, so the model of the [harness](../reference/glossary.md#harness) does not retype them. A second process, the [tap](../reference/glossary.md#tap), records what the agent received and sent. The [audit](../reference/glossary.md#audit) compares the 2 records byte for byte and names each [break](../reference/glossary.md#break). A [seal](../reference/glossary.md#seal) shows each file that changed after the end of the test.
>
> **What the records show**
>
> - In 4 setups, 10 of 10 messages reached the agent byte for byte, and 10 of 10 replies reached the [tester](../reference/glossary.md#tester) byte for byte. The setups are the plugin and the [project hooks](../reference/glossary.md#project-hooks), each in Claude Code 2.1.302 and in Codex 0.169.0.
> - In each of the 4 setups, the audit found 5 of 5 planted faults: an altered reply, an unshown reply, an altered input, an injected input and a missing record.
> - In each of the 4 setups, the model tried to call the agent directly, the [relay](../reference/glossary.md#relay) denied the call, and the agent received nothing.
>
>   Data for these 3 results: [plugin in Claude Code](../../proofs/plugin-claude-code/results.json), [plugin in Codex](../../proofs/plugin-codex/results.json), [project hooks in Claude Code](../../proofs/hooks-claude-code/results.json), [project hooks in Codex](../../proofs/hooks-codex/results.json). Method: [proofs_relay.py](../../scripts/proofs_relay.py).
> - A toy shop app sent its spans to Phoenix and made no span for 1 of its 2 backend calls. Phoenix had 1 span. Nookku recorded 2 calls and named the call with no span ([data](../../proofs/inapp-trace/results.json), [method](../../scripts/proof_inapp_trace.py)).
> - In a kind cluster, the tap reached a toy shop agent behind a Service. In each of 3 forms of the tap, 5 of 5 messages and 5 of 5 replies were exact. This proof ran no harness and no model ([data](../../proofs/cluster-tap/results.json), [method](../../scripts/proof_cluster_tap.py)).
> - A recorded test replayed 10 of 10 times with no changed turn, after the stock service and the model API of the test stopped. A planted change of the app gave 3 [findings](../reference/glossary.md#findings) and a failed verdict ([data](../../proofs/replay/results.json), [method](../../scripts/proof_replay.py)).
>
> **What is new in 0.6.0**
>
> - **A gate run.** A gate file declares a set of [scripted tests](../reference/glossary.md#scripted-test). `nookku gate run` gives 1 sealed result and 1 aggregate verdict, and it names the build with a digest that you supply. A CI job or a release step reads the exit code.
> - **A replay.** `nookku replay --recorded` runs a recorded test again with the recorded answers of its backends. A changed turn is a finding.
> - **Answer keys.** The app spec can name a file of expected values. The [trace](../reference/glossary.md#trace) compares the replies with it, and the relay denies a model tool call that names the key file.
> - **More that the trace finds.** A reply citation that no tool result holds, an action with no approval, a call that the in-app trace does not show, and a tool call that a second message of the user stopped.
> - **An agent in a cluster.** The tap reaches an agent behind a Service in a Kubernetes cluster. The trace reads the egress spans and the App ingress spans of Koodam. A harness that runs in a pod, and an evaluation inside a restricted Workspace, are later work.
>
> **What this does not show**
>
> The agents in the proofs are toy agents. Each proof is a small number of runs, and the data says how many. The deny of a direct model call is best effort. [The limits page](../limits.md) gives each gap that I know.
>
> Nookku is local and has no runtime dependencies. The records stay in your project. [The results page](../results.md) has each proof, with its data and its method.

- **The benchmark.** [results.md](../results.md#2-benchmark-under-pressure) has a benchmark of 500 turns in each harness with 0 breaks. Its records are from Claude Code 2.1.288 and Codex 0.160.0, and #526 does not list it. If #525 runs it again, the text can get 1 line for it.
- **Counts of features.** The text gives no count of checks, metrics or cases, and no claim of scale or of simulation volume. #526 forbids them.
- **A harness in a pod, and an evaluation in a restricted Workspace.** [#431](https://github.com/mohanraj00/nookku/issues/431) and [#555](https://github.com/mohanraj00/nookku/issues/555) moved to a later release. The text names them as later work, with no date, and gives no result for them. The record of nookku 0.5.7 in a Workspace stays in [results.md](../results.md#claude-code-in-a-koodam-workspace), and the text does not use it.
